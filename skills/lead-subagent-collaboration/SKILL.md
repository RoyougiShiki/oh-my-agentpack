# 主代理—子代理协作模式

本 skill 由用户手动调用。调用后，它定义当前工作的协作边界；模型不得因为任务内容自行触发本 skill。

## 1. 角色分工

- **主代理**负责理解用户目标、分析事实、讨论取舍、设计方案、决定是否需要委派，以及审查子代理结果。
- **子代理**负责主代理明确委派的调查、实现、测试或其他执行工作。除非用户明确改变本边界，子代理只返回客观事实、实际修改、实际测试结果和失败信息，不自行做分析、设计、方案选择或范围扩张。
- 需要用户裁决的事项由主代理向用户提问。子代理可以提供裁决所需事实，但不能替用户形成裁决。
- 主代理不把“子代理完成了”当作“方案正确”或“验证通过”；必须独立抽查与用户目标相关的结果。

## 2. 子代理模型必须明确

每次委派子代理前，必须有明确的 `provider` 和 `model`。不得省略它们，不得依赖平台默认模型、当前会话默认模型或“自动选择”。

- 用户已经明确指定了本次使用的 provider 与 model 时，按该指定调用，并在调用参数中再次明确写出完整标识。
- 用户没有指定时，先查询当前可用模型，列出准确的 provider/model 标识和必要的简短差异，向用户建议一个选择并等待用户指定；不得先启动子代理再补问模型。
- 只有模型标识确认且当前路由可用时才委派。路由不可用时报告事实，不静默替换为其他模型。
- 如果一个模型有多个推理档位，按用户指定的档位调用；用户未指定时可以给出建议并等待选择。推理档位不能替代 provider/model。

## 3. 委派前写清任务契约

每个子代理任务都要有自包含的详细指令，至少写清：

1. **目标**：要调查或执行的具体结果。
2. **范围**：允许读取、修改或验证的文件、目录、服务和远端资源。
3. **禁止事项**：不得读取、修改或操作的对象；不得自行扩展的范围。
4. **事实标准**：需要返回原文、来源、行号、变更、命令、退出码、测试结果或失败原因中的哪些内容。
5. **完成条件**：什么结果才算完成，什么情况必须停止并报告。
6. **并发与写入边界**：是否能与其他任务并行，允许修改的 disjoint scope 是什么。

调查任务要求子代理区分“实际读取到的事实”和“没有取得的信息”；不能把没有找到证据说成不存在。修改任务要求子代理先理解允许范围，保持无关内容不变，并返回实际 diff、测试命令和退出码。

## 4. 委派边界

- 调查、代码修改、测试、构建、部署或其他需要执行的工作，交给子代理；主代理保留分析、设计、用户讨论和抽查审查。
- 不把“请你想一个方案”“请你评价取舍”“请你替用户做决定”作为默认子代理任务。需要这些内容时由主代理完成，或先取得用户明确改变分工的指令。
- 让子代理修改共享工作区时，先拆成互不重叠的写入范围；涉及同一文件或同一记录的任务必须串行，并把前一项结果作为后一项输入。
- 子代理不得自行再委派其他代理。需要扩大范围时，先停止并报告，交由主代理重新分派。

## 5. 等待与进度

- 委派在后台运行且主代理没有其他独立工作时，主代理直接等待完成通知。
- 不频繁调用状态查询、重复读取子代理修改或轮询“是否快完成”。只有收到完成通知、出现失败，或用户明确要求进度时，才做必要的核对。
- 有其他不依赖该子代理的工作时，可以继续做；多个互相独立的任务应在同一轮并行委派。
- 子代理失败、超时或返回不完整时，记录已完成部分；不要盲目重复可能已经成功的写入，先核对实际状态再决定是否重试。

## 6. 结果接收与主代理审查

子代理返回后，主代理至少检查：

- 是否使用了指定的 provider/model，任务范围是否越界；
- 返回的是可核验事实和实际结果，而不是未经授权的分析或设计；
- 修改是否只落在批准范围，测试是否真的执行，退出码是否成功；
- 是否需要把已形成的结论、任务状态或验证证据写回原记录；
- 未验证、未运行、未部署和失败项是否如实保留。

“读取到了 skill”“调用过工具”“测试命令写在报告里”都不能单独证明行为正确；需要根据任务的外部结果和实际证据抽查。

## 7. 用户控制与安全边界

- 用户可以随时缩小范围、改变模型、暂停或取消委派；主代理不得把默认协作模式解释成用户授权。
- 子代理不得擅自发布、删除、花费、修改凭证、改变宿主配置、重启服务或执行其他高影响动作；任务契约必须明确这些动作是否获准。
- 用户没有批准的持久写入、远端写入或部署动作，先停在草案或报告事实，不自行执行。
- 本 skill 只规定协作方式，不复制项目裁决、专业 skill 规则或第三方导航内容；具体项目仍按其有效裁决和专业规则工作。

## 8. 推荐的委派指令形状

委派时可以使用以下结构，按实际任务删减，不要让子代理自行补全缺失的授权：

```text
你只负责按本指令执行，不分析、不设计、不提出额外方案、不扩大范围、不再委派。

目标：
范围：
允许的读取：
允许的写入或执行：
禁止事项：
返回的客观事实与证据：
完成条件：
失败或信息不足时：
```

本 skill 的完成条件不是“始终使用子代理”。在用户授权后，主代理仍可判断哪些工作需要委派；不需要执行工作时，主代理可以自己完成分析、设计和讨论。
