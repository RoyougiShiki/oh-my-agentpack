# Goal Draft

1. 理解任务：从当前对话优先，其次项目中的计划/决策/验收类文档（任意形式），理解完成标准、范围约束、失败条件。找不到就问用户，不要硬猜。

2. 起草契约：目标 + 可验证的完成标准 + 范围边界 + 失败兜底（什么情况停下汇报）。简洁陈述，呈现给用户。

3. 等待用户明确确认后再启动；用户修改则按修改更新契约。确认前不执行任务、不调用 goal 工具。

4. 启动方式按当前环境探测：有 goal 工具（如 create_goal）则调用；否则输出契约文本供用户自行使用。不与任何特定工具绑定。

5. 若环境有任务列表工具，确认后可将契约拆分为任务同步跟踪；没有则跳过。

6. 确认后直接执行，不重复起草、不重复询问。
